# WebDAV 与 S3 同步

设置中的“云存储”选择 WebDAV 或 S3，同一时间只启用一种。两套配置分别保存；旧版仅有 WebDAV 的配置自动沿用。配置及密钥使用 Android Keystore 加密保存。

保存配置不会启动同步。返回列表点击“立即同步”开始；后台同步、暂停、继续和网络恢复重试适用于两种方式。正在同步时先停止任务再修改配置；保存会终止旧的等待或暂停任务，防止旧目标继续运行。

## S3 配置

- Endpoint：服务商提供的 HTTPS S3 API 地址，不含账号、查询参数和 Bucket 名称（Bucket 单独填写）。
- Region：按服务商说明填写，如 AWS 的 `us-east-1`、Cloudflare R2 的 `auto`。
- Bucket：已存在的存储桶，不自动创建。
- Access Key ID / Secret Access Key：具有下面权限的访问密钥。
- 存储前缀：默认 `DailyOne/`，留空使用 Bucket 根目录。
- 高级设置“路径式访问”：按服务商要求启用，例如部分 MinIO 部署。

采用 AWS SDK for Kotlin 1.3.83，与项目现有 Kotlin 2.0 和 Android API 26 配置兼容。服务商的 S3 兼容性需要以实际实例验证为准。

对象结构与 WebDAV 一致：

```
DailyOne/notebooks/<id>.json
DailyOne/entries/<id>.json
DailyOne/photos/<图片或视频文件名>
```

S3 列举完整处理 `ListObjectsV2` 分页，ETag 仅用于版本比较，不当作文件 MD5。普通 S3 服务的日记和日记本采用条件写入：新增 `If-None-Match: *`，更新 `If-Match: <ETag>`。条件失败时保留本地修改，重新同步后按冲突副本处理。七牛官方 `*.qiniucs.com` Endpoint 使用下述只追加版本格式，以及 `ListObjects` 的 Marker 分页；普通 S3 保持 `ListObjectsV2`。原始图片与视频流式上传下载；失败后按文件重试，已上传的媒体跳过，不重新压缩，不提供单个大文件的分片续传。

每次同步使用两个独立的 `<前缀>.checks/<随机UUID>.json` 对象分别验证：

- `If-None-Match` 新增保护：允许创建新对象，拒绝重复创建，拒绝后原内容和 ETag 必须保持不变。
- `If-Match` 更新保护：拒绝不匹配的 ETag，拒绝后内容保持不变；正确 ETag 能更新且版本标记变化。

检测结果分别显示“通过 / 失效”，同步连接阶段及 `DailyOneS3` 日志中可以查看。日志只包含能力结果和使用的同步方式，不包含地址、Bucket、密钥、日记或请求正文。网络/认证失败会报错，不会误判为“不支持”。清理检查对象失败也不会掩盖已经发生的原始异常。

普通 S3 服务缺少任一能力会停止同步。七牛使用只追加版本保存冲突保护，可以继续同步。检查只删除本次生成的检查对象，不删除日记或媒体对象。

所需权限：

- `s3:ListBucket`：允许列举配置的前缀。
- `s3:GetObject`、`s3:PutObject`：配置前缀下的对象。
- `s3:DeleteObject`：仅需要配置前缀下 `.checks/` 检查对象的权限。

无需桶创建权限、公开读权限，也不需要日记和媒体的物理删除权限。取消或网络中断时可能留下少量检查对象，不影响后续同步。

## 七牛兼容与冲突保护

七牛官方 Endpoint 示例为 `https://s3.cn-south-1.qiniucs.com`，Bucket 单独填写，Endpoint 中不要再次填写桶名。

针对不可靠执行标准条件 PUT 的服务，先查询再覆盖无法防止两个客户端同时写入。七牛适配采用不可覆盖的完整版本对象：

```
<前缀>.versions/entries/<日记ID>/<父版本SHA256或root>.<本版本SHA256>.json
<前缀>.versions/notebooks/<日记本ID>/<父版本SHA256或root>.<本版本SHA256>.json
```

- 每次修改保存为独立对象，正文包含父版本和完整日记/日记本；文件名使用完整内容的 SHA-256。相同版本重试只写入相同字节，不覆盖其他版本，不依赖可变索引或最后写入的指针。
- 列举版本关系后选取尚未被后续版本承接的版本。两个设备从同一父版本并发修改时，两条分支都保留；额外分支生成固定 ID 的冲突副本，其后编辑或删除不会反复生成原来的同一副本。
- 删除仍是一个新版本中的删除标记。与删除并发的新修改保留为活跃记录；历史对象不删除。
- 写入后读回验证，读取时验证版本内容与 SHA-256、日记编号、父版本关系；缺失父版本或内容校验不符时停止同步，不静默丢弃版本。
- 原有 `entries/`、`notebooks/` 文档会保留并归档为根版本，不覆盖或删除原文件。照片和视频继续使用原有文件名和 `photos/` 路径，已存在媒体不会由适配器重新上传覆盖。

七牛多设备同步需要所有参与设备使用支持此版本格式的新客户端。不要用旧客户端或第三方工具覆盖、清理这些版本对象；本次不提供历史清理功能。版本目录随修改增加，占用的存储会多于只保存最新 JSON 的方式。

兼容性通过本机模拟七牛忽略一个或两个条件头的服务验证，未使用真实账号，也未连接用户手机或七牛实例。旧版的合并错误提示不能证明实站具体忽略了哪一个条件头；新版独立检测结果用于确认。

### 上传超时诊断

七牛兼容分支对应用当前使用的已知长度上传关闭 `Expect: 100-continue` 等待，直接流式发送正文。使用不返回 100 响应的本地服务测试 13 MB 原始文件上传，验证不带该头且文件字节一致。普通 S3 保留 SDK 默认握手行为。

进度栏与 `DailyOneS3` 日志区分列举、上传、读取版本、检查及上传媒体；超时提示保留当前操作名称。日志不输出配置、对象 ID、文件名、请求正文或密钥。网络超时仍保留本地修改并交由后台任务重试，不降低版本校验或冲突保护。

`SocketTimeoutException` 本身不能证明实站是握手超时；新诊断用于进一步区分上传和读回等阶段，不将所有超时归因于同一原因。

## 切换目标

切换 provider、服务器/账号、Bucket 或前缀等目标信息后，在下次同步开始时，以数据库事务重建同步基线，旧目标的 ETag 不会用于新目标。密码/Secret Access Key 轮换不会重建基线。

- 仅本机存在：上传到目标。
- 仅目标云端存在：下载到本机。
- 同 ID、相同内容：关联到新目标的版本，修改时间差异不会产生冲突副本。
- 同 ID、内容不同：保留本地冲突副本和云端版本。
- 云端缺少记录不表示删除；删除仍使用记录中的删除标记传播。

本机内容与旧目标对象不会因为切换而被清空。不提供自动搬迁或自动清理旧云端。候选正文和媒体仍不参与云同步，已处理图片的内容指纹独立同步。

## 扫描去重历史

WebDAV 和 S3 新增指纹使用 `scan-history-batches/<批次正文SHA-256>.json` 保存只追加的已处理内容集合，每批最多 512 条，正文为 `{"version":1,"hashes":["..."]}`，指纹排序去重后生成不可变批次。继续读取旧版 `scan-history/<64位小写SHA-256>.json`，不删除或改写已完成的旧记录。包括已加入日记、右滑删除/未保留的候选图片和检测后没有人物的照片。只同步指纹，不上传未保留原图、相册路径或候选正文。

批次摘要校验完整正文，再验证版本、数量和指纹格式；同一个键只有一种合法内容；并发上传同一指纹幂等，兼容七牛忽略条件头的行为，不改变日记的条件写入和版本冲突保护。上传前在本地持久化批次；上传读回核对后，在一个事务内确认整批指纹和批次回执。失败或应用重启时复用原批次，只继续未确认部分；不确定的上传通过云端同 ID 批次读回确认。成功批次不会再次上传，进度显示累计完成条数。设备之间、切换目标时取并集，云端缺少指纹不视作删除。

多设备都应升级到支持批次格式的版本；旧版客户端无法读取新增的批次去重记录。卸载前必须完成同步，重装后先同步再扫描。旧版记录的补齐规则和精确字节匹配的边界见[人物照片扫描说明](photo-scan.md)。

## 本地验证

执行 `./gradlew testDebugUnitTest lintDebug assembleDebug`。S3 协议测试使用本机 MockWebServer；同步与数据库迁移测试使用本机 Robolectric，覆盖分页、两项条件检查独立失效、只追加版本的并发修改/删除、冲突副本后续编辑/删除、版本校验、媒体原字节、失败重试、双向切换、冲突保留和旧库迁移。不连接真实云端，不读取或操作手机。
